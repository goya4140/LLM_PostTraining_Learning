## 1. 为什么需要 PEFT？

全量微调（Full Fine-tuning）的代价：

```
模型参数量    FP32 显存    AdamW 优化器状态（×3）
─────────────────────────────────────────────
Qwen2.5-7B    28 GB         84 GB
Qwen2.5-72B  288 GB        864 GB
```

**核心矛盾**：预训练模型的大部分参数已经足够好，微调只需调整一小部分方向（任务相关的低维子空间）。

**PEFT 的核心假设**：微调过程中，权重变化矩阵 ΔW 的内在秩（intrinsic rank）远低于矩阵维度。  
这一假设由 [Aghajanyan et al. 2021](https://arxiv.org/abs/2012.13255) 的 intrinsic dimensionality 实验支撑。

## 2. 低秩分解的数学直觉

矩阵的秩衡量其「信息量」。一个 `d×k` 的满秩矩阵有 `d×k` 个自由度，但大量自然出现的变化矩阵具有低秩结构：

```
满秩矩阵 ΔW (768×768)：
┌─────────────────────────────────────┐
│  ×  ×  ×  ×  ×  ×  ×  × ... (768列) │   参数量 = 589,824
│  ×  ×  ×  ×  ×  ×  ×  ×            │
│  ... (768行)                        │
└─────────────────────────────────────┘

秩-8 分解 ΔW = B·A：
    B (768×8)      A (8×768)
┌────────────┐  ┌──────────────────────┐
│ ×  ×  ×  × │  │ ×  ×  ×  ×  × ...   │   参数量 = 768×8 + 8×768
│ ×  ×  ×  × │  │ ×  ×  ×  ×  ×       │          = 12,288 (~2%)
│ ...        │  └──────────────────────┘
└────────────┘
         ↑
    秩瓶颈（rank bottleneck）
```

**关键洞察**：如果 ΔW 的真实秩是 r，用 r 个基向量就能精确表达，不损失任何信息。

## 3. LoRA 数学推导

### 3.1 基本公式

对于预训练权重矩阵 `W₀ ∈ ℝ^{d×k}`，LoRA 将前向传播改写为：

```
h = W₀·x + ΔW·x
  = W₀·x + B·A·x

其中：
  B ∈ ℝ^{d×r}，A ∈ ℝ^{r×k}，r ≪ min(d, k)
  W₀ 冻结（requires_grad=False）
  B, A 可训练（requires_grad=True）
```

### 3.2 缩放因子 α/r

LoRA 实际使用缩放版本：

```
ΔW_scaled = (α / r) · B · A
```

**为什么需要缩放？**

- 当改变 r 时，学习率需要跟着调整（不同 r 下 ΔW 的数值范围不同）
- 引入 α 作为独立超参数后，固定 `lr` 不变，通过 `α/r` 控制 ΔW 的整体缩放幅度
- 惯例：`α = 2r`（如 r=8, α=16），此时 `α/r = 2`，相当于将学习率×2

### 3.3 初始化策略

```python
# B 初始化为零（关键！）
self.lora_B = nn.Parameter(torch.zeros(out_features, r))

# A 使用 Kaiming uniform 初始化（与 nn.Linear 一致）
self.lora_A = nn.Parameter(torch.empty(r, in_features))
nn.init.kaiming_uniform_(self.lora_A, a=math.sqrt(5))
```

**为什么 B=0？**  
确保训练开始时 `ΔW = B·A = 0`，即 LoRA 模型在第 0 步与原始预训练模型完全等价。
避免了随机初始化引入的噪声扰动影响训练稳定性。

### 3.4 推理时权重合并

推理时可将 ΔW 合并进 W₀，**不引入额外延迟**：

```
W_merged = W₀ + (α/r) · B · A
```

合并后等价于标准 `nn.Linear`，推理速度与全量微调模型相同。

## 4. 梯度流分析

```
前向传播：
  x → [冻结 W₀] → base_out
  x → [可训练 A] → [可训练 B] → lora_out × (α/r)
  output = base_out + lora_out

反向传播（链式法则）：
  ∂L/∂B = (∂L/∂output) · (A·x)ᵀ · (α/r)
  ∂L/∂A = Bᵀ · (∂L/∂output) · xᵀ · (α/r)
  ∂L/∂W₀ = 0  ← 冻结，梯度不更新
```

**梯度维度**：
- `∂L/∂B` 形状 `[d, r]` — 比全量 `[d, k]` 小 `k/r` 倍
- `∂L/∂A` 形状 `[r, k]` — 比全量 `[d, k]` 小 `d/r` 倍

显存节省来自两方面：
1. 优化器状态（AdamW 需要 m, v）只针对 A, B 而非 W₀
2. 不需要存储 W₀ 的激活值用于反向传播（`requires_grad=False`）

## 5. 参数压缩率计算

```
原始参数量（单层 Linear）：d × k
LoRA 参数量：r × k + d × r = r(d + k)

压缩率 = r(d+k) / (d×k)
        ≈ r × (1/k + 1/d)    （对于正方形矩阵 d=k）
        = 2r / d

例子：Qwen2.5-0.5B 的 q_proj (d=896, k=896, r=8)
  LoRA 参数 = 8 × (896 + 896) = 14,336
  Full 参数 = 896 × 896 = 802,816
  压缩率 = 14,336 / 802,816 ≈ 1.79%
```

**注入所有注意力层后的全局压缩率**（Qwen2.5-0.5B 为例）：

| 注入目标 | 每层 LoRA 参数 | 可训练总参数 | 占比 |
|---------|-------------|------------|------|
| q_proj + v_proj（r=8） | ~28K | ~336K | ~0.07% |
| 所有 attention（r=8） | ~57K | ~683K | ~0.14% |
| 所有 attention + MLP（r=8） | ~168K | ~2.0M | ~0.41% |

## 6. 初始化设计的意义

**实验对比**（LoRA 原论文 Figure 1 的变体）：

| 初始化方式 | 第 0 步行为 | 训练稳定性 |
|-----------|-----------|----------|
| B=0, A~Kaiming | ΔW=0，模型与预训练等价 | ✅ 稳定 |
| B~N(0,σ), A~N(0,σ) | ΔW≠0，随机扰动 | ⚠️ 需要更小 lr |
| B=0, A=0 | ΔW=0，但梯度消失 | ❌ 不收敛 |

**直觉**：用 B=0 初始化，相当于「先继承预训练模型的全部能力，再逐步学习任务特定的调整」。

## 7. PEFT 方法横向对比

| 方法 | 可训练参数位置 | 推理开销 | 参数量 | 适用场景 |
|------|-------------|---------|--------|--------|
| **LoRA** | 注意力/MLP 权重的低秩矩阵 | 合并后无开销 | ~0.1-1% | 通用微调首选 |
| Adapter | 层间插入瓶颈 MLP | +2 个线性层延迟 | ~0.5-3% | 多任务（保留原始层） |
| Prefix-Tuning | 输入前置可训练向量 | 额外 KV Cache | ~0.01-0.1% | 生成任务，无需改模型结构 |
| IA³ | 缩放向量（element-wise） | 合并后无开销 | ~0.01% | 极低参数场景 |
| Full FT | 所有参数 | 无 | 100% | 数据充足时的上限 |

**LoRA 成为标配的原因**：推理零开销 + 参数量极低 + 效果接近全量微调。

## 8. 秩 r 的选择指南

```
任务复杂度                建议 r    说明
─────────────────────────────────────────────
简单风格迁移 / 领域适配     4-8     大多数场景足够
指令遵从 / 问答微调         8-16    Qwen2.5 默认推荐
代码生成 / 数学推理         16-32   高复杂度任务
全新能力习得（罕见）        64+     接近全量微调效果
```

**关于 α 的设置**：
- 常见选择：`α = r`（scaling=1）或 `α = 2r`（scaling=2）
- `α = 2r` 等效于将 LoRA 学习率乘以 2，一般效果更好
- 不要把 α 设得过大（>64）：相当于大幅提高 LoRA 学习率，可能不稳定

**多层注入策略**：
- 只注入 `q_proj + v_proj`：参数最少，通常已足够
- 加入 `k_proj + o_proj`：更强的注意力学习能力
- 再加 `gate/up/down_proj`：覆盖 MLP，适合知识注入类任务

## 10. 常见问题

**Q: r 太小（r=1-2）会怎样？**  
A: 表达能力不足，ΔW 被限制在 1-2 维子空间，模型可能无法习得任务。表现为 loss 下降缓慢或停滞。

**Q: r 太大（r=256）会怎样？**  
A: 接近全量微调，但优化更难（更多参数），且失去了低秩的正则化效果，可能过拟合。

**Q: 为什么 MPS 设备上 4-bit 量化有限制？**  
A: `bitsandbytes` 的 4-bit（NF4）kernel 依赖 CUDA 特性，MPS 上只支持权重加载，不支持 4-bit 计算。实际在 M4 Pro 上，`float16` + LoRA 已足够（0.5B 模型仅需 ~1GB 统一内存）。

**Q: 注入 LoRA 后，原始模型权重在哪里？**  
A: `inject_lora` 中通过 `lora_layer.weight = module.weight` 共享张量，原始权重仍然存在（只是 `requires_grad=False`），不占用额外显存。

**Q: 合并权重后如何恢复原始模型？**  
A: 合并是不可逆的（`W_merged = W₀ + ΔW`）。最佳实践是保存 LoRA 权重（`get_lora_state_dict`），需要时重新注入到新加载的基础模型上。
